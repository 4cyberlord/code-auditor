# Phase 6.6 — Trusted benchmark feed operations

Adaptive routing is safe to operate without any benchmark feed: unknown accuracy remains unknown, and no model receives a signed specialist ranking bonus.

## Deployment configuration

Provide these at **build time** for the desktop/Next.js application:

- `NEXT_PUBLIC_COUNCIL_BENCHMARK_FEED_URL`: deployment-controlled HTTPS URL serving one signed benchmark report (JSON).
- `NEXT_PUBLIC_COUNCIL_BENCHMARK_P256_JWK`: the corresponding **public-only** P-256 JWK; never include the `d` private parameter.

The JWK is publicly embedded in frontend code by design. **Never** put the signing private key in a `NEXT_PUBLIC_*` variable. Store private signing material offline with the trusted benchmark operator. If either value is missing, malformed, unreachable, or fails signature verification, the app falls back to no historical accuracy evidence.

## Provenance and admission rules

Only independently reviewed fixture evaluations are eligible. A score, council consensus, AI judge vote, manually edited setting, or a report declaring itself verified is **not** sufficient evidence. Sign reports only after validating the fixture source, execution isolation, output comparison, model identity, and fixture IDs outside the candidate execution sandbox.

The report must contain one outcome per unique (model, fixture ID); it is signed with P-256/SHA-256 over the exact JSON payload. The application verifies the signature against the independently pinned public key and uses at least 20 verified outcomes to rank specialist accuracy. It never treats a signed report as proof of screenshot vision, model availability, endpoint support, or current price.

## Operator process

1. Prepare and review a fixed benchmark manifest and expected outputs. Never use answers generated by candidates as reference output.
2. Run candidates in the explicitly isolated benchmark runner. Keep secrets and network access outside the execution sandbox.
3. Inspect outputs and provenance. Sign verified outcome JSON using `scripts/sign-benchmark.mjs` with an operator-managed private P-256 JWK.
4. Publish the signed JSON report over HTTPS, configure the deployment's URL and pinned **public** JWK, and rebuild.
5. Check that stale, unsigned, tampered, missing-key, or unreachable feeds do not produce accuracy boosts. Rotate the key and rebuild when the signer changes.

## Release gate

PR validation covers Node typechecking/tests, lint, Rust checks, macOS unsigned build, and Docker containment. The E2B live smoke test requires an explicit trusted-branch workflow dispatch with credentials and is **not** covered by normal pull requests.

Do not claim a signed/notarized macOS release or a functioning live benchmark feed until actual production provisioning, trusted-run smoke checks, and macOS signing/notarization are independently verified.
